Это проект веб-сайта, позволяющего переводить цвета из одной системы в другую, а также одновременно с этим визуализировать полученные цвета.

  Задача проекта:
Создать приложение/веб-приложение, позволяющее пользователю выбирать, а
затем интерактивно менять цвет, показывая при этом его составляющие в трех
моделях одновременно.

  Основные требования к проекту:
В интерфейсе дать возможность пользователю задавать точные цвета (поля
ввода), выбирать цвета из палитры (аналогично графическим редакторам), плавно
изменять цвета (например, ползунки).
При изменении любой компоненты цвета все остальные представления этого
цвета в двух других цветовых моделях пересчитываются автоматически.
При «некорректных цветах» (например, при переходе из XYZ в RGB в вашем
расчете получился выход за границы изменения рассчитываемого параметра)
выдавать некое ненавязчивое предупреждение, что происходит обрезание, округление и т.п.

  Дополнительные требования:
1. Все расчеты должны производиться вручную. При использовании внешних библиотек конвертации работа не будет засчитана.
2. Жестких констант для перевода в модель XYZ и LAB быть не должно. Также в интерфейс необходимо добавить выбор стандарта освещения: D65 (средний дневной свет, стандарт для sRGB), D50 (теплый дневной свет, стандарт для полиграфии) или E (равноэнергетический источник). При смене стандарта программа должна автоматически пересчитывать матрицы перехода на лету.
3. Для расчета CMYK: программа должна поддерживать полноценный перевод с возможностью выбора одного из алгоритмов цветоделения:
UCR (Under Color Removal / Удаление подложечного цвета): уменьшение количества цветных компонентов (CMY) в глубоких тенях и замена их на черную (K).
GCR (Gray Component Replacement / Замена серой компоненты): замена серой составляющей, образованной тремя цветными компонентами, на одну черную во всем диапазоне цветов.
4. При выходе цвета за рамки возможностей модели (например, из XYZ в RGB), вместо простого обрезания до 0 или 255 реализовать одну из двух стратегий:
Clipping (Обрезание): значение просто прижимается к границе (например, 270 превращается в 255).
Scaling (Масштабирование): весь диапазон цветов сжимается пропорционально, чтобы «втиснуть» цвет в рамки.
5. Динамические градиенты на ползунках (Слайдерах). Фон под ползунком должен интерактивно меняться. Например, если пользователь двигает ползунок «R» (Красный) в модели RGB, фон под ползунками «G» (Зеленый) и «B» (Синий) должен показывать, какой цвет получится, если сдвинуть их прямо сейчас при текущем уровне красного.

ДЛЯ ОЦЕНОК 8-10:
1. Разделить код программы на независимые слои:
Model (Модель): чистая математика перевода цветов, которая ничего не знает про интерфейс.
View (Представление): только внешний вид (кнопки, ползунки), интерфейс.
ViewModel / Controller (Связующее звено): логика, которая берет данные из интерфейса, передает их в математику и возвращает результат обратно.
2. Написать автоматические микро-тесты для проверки математики. Например, тест должен автоматически подавать на вход функции значения RGB(255, 0, 0) и проверять, выдает ли она строго правильные координаты в LAB и CMYK.

Я получил вариант 3. Для данного варианта требовалось создать конвертер RGB ↔ XYZ ↔ LAB.

В результате работы создано веб-приложение lab1.html, работающее в браузере. Оно показывает цвет одновременно в RGB, XYZ и CIELAB. Для каждой модели есть три способа задания: числовые поля, ползунки и палитра. При изменении любой компоненты контроллер автоматически пересчитывает две другие модели и обновляет предпросмотр. Все расчёты выполнены вручную, без внешних библиотек. Матрица RGB ↔ XYZ не задана жёсткими константами, а строится из координат первичных цветов sRGB и белой точки выбранного освещения. Поддерживаются D65, D50 и E. При смене стандарта матрицы и LAB пересчитываются на лету. Переход XYZ ↔ LAB реализован по формулам CIE с пороговой функцией.

При выходе из XYZ или LAB в RGB за пределы 0-255 доступны Clipping и Scaling. Пользователь видит предупреждение с исходными значениями и указанием, что было применено. Ползунки имеют динамические градиенты: фон показывает, какой цвет получится при изменении данной компоненты при текущих остальных. Интерфейс выполнен в тёмной теме, адаптируется под узкие экраны.
Код разделён на слои ColorModel, ColorView и ColorController. ColorModel содержит только математику, ColorView отвечает за интерфейс, ColorController связывает их. При загрузке запускаются микро-тесты: проверка матрицы D65, RGB(255,0,0) → XYZ и LAB, round-trip, смена освещения, белая точка E и Scaling. 
Вариант 3 требует только RGB, XYZ и LAB, поэтому CMYK, UCR и GCR в данной работе не используются. При необходимости модель можно расширить без изменения интерфейса. 

Таким образом, приложение закрывает обязательные требования варианта 3: 3 модели, 3 способа ввода, автопересчёт, предупреждения о выходе за границы, выбор освещения, ручные формулы, динамические градиенты, MVC и микротесты.
